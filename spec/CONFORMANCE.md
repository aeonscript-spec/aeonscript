# AeonScript Conformance Suite

**Version** : v0.1
**Last updated** : 2026-06-07
**Status** : initial

This document defines what it means to be a **conformant** AeonScript implementation, and provides the canonical test vectors against which any implementation MUST validate.

---

## 1. Levels of conformance

A conformant implementation is classified by which **L1 profile** and which **L4 codec** it supports.

| Conformance level | Required layers | Required profiles |
|------|------|------|
| **Level 0** — Tag parser only | L5 | (none — read-only) |
| **Level 1** — Minimal codec | L1, L5 | L1-4 |
| **Level 2** — Recommended | L1, L4, L5 | L1-4, `rs255-223` |
| **Level 3** — Full v0.1 | L1, L4, L5 + hazard screening (§9) | L1-4, `rs255-223` |
| **Level 4** — Reserved | L1, L2, L3, L4, L5 | TBD (v0.2) |

A v0.1 implementation **MUST** declare its conformance level in published documentation.

## 2. Canonical test vectors

Test vectors live in [`test-vectors/`](test-vectors/). Each vector specifies:

- An **input** : payload bytes (hex), block_id, mime_type.
- The **expected** output : L5 tag, oligo count, total bases, exact oligo sequences.

A conformant **encoder** MUST produce the exact `oligos` array byte-for-byte for each input.
A conformant **decoder** MUST round-trip each `oligos` array back to the exact input bytes.

### 2.1 L1+L5 vectors (no error correction)

[`vectors-l1-l5.json`](test-vectors/vectors-l1-l5.json) — 10 vectors covering:

| Vector ID | Description |
|---|---|
| `tv-01-empty` | Empty payload (edge case) |
| `tv-02-ascii-short` | Short ASCII text |
| `tv-03-ascii-long` | Longer ASCII text spanning multiple oligos |
| `tv-04-binary` | Arbitrary binary bytes (0x00..0x3F) |
| `tv-05-all-zeros` | 32 bytes of 0x00 (homopolymer-stressing input) |
| `tv-06-all-ones` | 32 bytes of 0xFF (homopolymer-stressing input) |
| `tv-07-utf8` | UTF-8 with accented Latin characters |
| `tv-08-json` | Small JSON document |
| `tv-09-emoji` | UTF-8 with multi-byte emoji |
| `tv-10-medium` | Medium-length repetitive ASCII (compression-stressing) |

### 2.2 L1+L4+L5 vectors (with Reed-Solomon)

Reserved for v0.1.1. The current Python reference (using `reedsolo`) defines the canonical RS-encoded outputs; tooling to extract them as JSON test vectors is on the roadmap.

### 2.3 Negative tests

Inputs that a conformant encoder MUST reject:

- MIME type containing `;`, `=`, or `|` (e.g. `"text/plain; charset=utf-8"`) — must raise an error per SPEC §4.5.
- `block_id` containing the same reserved characters.
- Oligo length `< 64` bases (insufficient overhead for prefix + meaningful payload).
- Payload length `> 2^31 − 1` bytes (out of LEN field range).

## 3. Generating the vectors

The L1+L5 vectors are generated by:

```bash
node spec/test-vectors/generate.js
```

The generator script ([`test-vectors/generate.js`](test-vectors/generate.js)) is itself part of the reference and SHOULD be kept synchronised with the algorithms documented in SPEC §2 (L1) and §4 (L5).

If you discover a discrepancy between the generator and SPEC, **the SPEC wins** — please open an issue.

## 4. Validating an implementation

A conformant implementation should expose a test harness that, given the vectors JSON, validates:

### For encoders

For each vector `v`:

```python
input_bytes = bytes.fromhex(v["input"]["payload_hex"])
produced = encoder.encode_bytes(
    input_bytes,
    block_id=v["input"]["block_id"],
    mime_type=v["input"]["mime_type"],
)
assert produced == v["expected"]["oligos"], f"encoder mismatch on {v['id']}"
```

### For decoders

For each vector `v`:

```python
oligos = v["expected"]["oligos"]
recovered = decoder.decode_oligos(oligos)
expected_input = bytes.fromhex(v["input"]["payload_hex"])
assert recovered == expected_input, f"decoder mismatch on {v['id']}"
```

### Coverage requirement

A Level 1 implementation MUST pass **all 10 L1+L5 vectors**, encoder *and* decoder, for it to be advertised as "AeonScript v0.1 Level 1 conformant".

## 5. Reporting conformance

If you publish an AeonScript implementation, please open a PR adding a line to [`KNOWN_IMPLEMENTATIONS.md`](../KNOWN_IMPLEMENTATIONS.md) (file to be created) with:

- Implementation name and URL
- Language / runtime
- Declared conformance level
- Date validated
- Link to your test-harness output

This serves as the de-facto registry until a formal certification process exists (Phase 5 of the [ROADMAP](../ROADMAP.md)).

## 6. Vector format schema

```json
{
  "schema_version": "1.0",
  "generator": "string — relative path of the generator script",
  "generated_at": "ISO 8601 timestamp",
  "spec_version": "0.1",
  "l1_profile": "L1-4",
  "l4_codec": "none | rs255-223",
  "scrambler": { "algorithm": "xorshift32", "seed_hex": "deadbeef" },
  "oligo_length_target_bases": 200,
  "notes": ["..."],
  "vectors": [
    {
      "id": "tv-NN-name",
      "description": "...",
      "input": {
        "payload_hex": "hex-encoded bytes",
        "payload_len_bytes": 42,
        "block_id": "string",
        "mime_type": "string"
      },
      "expected": {
        "l5_tag_ascii": "|AEONSCRIPT=0.1;...|",
        "l1_profile": "L1-4",
        "l4_codec": "none",
        "oligo_count": 3,
        "total_bases": 460,
        "oligos": ["ACGT...", "ACGT...", "..."]
      }
    }
  ]
}
```
